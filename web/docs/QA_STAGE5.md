# Stage 5 — QA / Accessibility / Forms

## Реализовано

- skip-link на всех пользовательских маршрутах;
- управляемое мобильное меню с `aria-expanded`, Escape, закрытием после навигации и блокировкой прокрутки страницы;
- `aria-current` в desktop/mobile навигации;
- `/404`;
- `/robots.txt`, формируемый из `SITE`;
- `Practice` помечен `noindex` до закрытия OQ-01;
- существующая ссылка Footer `/privacy/` больше не ведёт на 404: добавлена временная `noindex`-страница;
- форма получила доступные labels, состояния ошибок, `aria-live`, `aria-busy`, honeypot и клиентскую валидацию;
- transport формы задаётся `PUBLIC_CONTACT_ENDPOINT` и не содержит секретов в браузере.

## Не закрыто

- реальный канал формы (OQ-02) не выбран, поэтому endpoint не фиксируется;
- временная `/privacy/` не является юридическим документом и должна быть заменена утверждённой политикой до production;
- server-side validation будет реализована вместе с конкретным server transport/hosting. Сейчас frontend отправляет JSON в заданный endpoint;
- Lighthouse / axe / реальные браузерные проверки нужно выполнить в окружении разработчика после production build.

## Проверка вручную

1. Tab с начала страницы должен первым фокусировать skip-link.
2. На ширине < 900px открыть меню, нажать Escape, повторить и перейти по ссылке.
3. Отправить пустую форму — должны появиться локальные ошибки и фокус на первом ошибочном поле.
4. При пустом `PUBLIC_CONTACT_ENDPOINT` валидная форма должна сообщить, что канал не настроен, без ложного сообщения об успешной отправке.
5. Проверить `/404`, `/robots.txt`, `/sitemap.xml`, `/practice/`, `/privacy/`.
